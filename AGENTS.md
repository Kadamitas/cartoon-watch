# Cartoon Watch

## Product and code

Use WCO/WCO Stream as the only main catalog. The bundled snapshot has 16,167 unique public links across dubbed anime, cartoons, subbed anime, movies, and OVA. AniWave, KissAnime, and HDToday are automatic playback fallbacks for the same title, known release year, season, and episode. Reject ambiguous matches; do not turn fallbacks into competing catalogs.

Home starts with weekly discovery or a neutral browse prompt, never the first alphabetical title as a default spotlight. AniList weekly ranking uses seven complete UTC days of community activity among the selected feed candidates; it is not a universal view count. Anime-category discovery uses all-time AniList list popularity, not review scores. Fighting maps to the Martial Arts tag. Preserve the shared registry in `app/src/main/assets/discovery-categories.json`: 20 specific anime categories and eight curated cartoon collections, generated into the shared UI and Roku by `tools/generate_discovery.py`. Isekai is the first anime choice. Respect the registry's source mappings and meaningful tag thresholds rather than admitting marginally tagged titles. Match only to existing WCO series through confident IDs, exact unique aliases, or the supported explicit season relationship; reject ambiguous matches and deduplicate combined series. Keep at most 20 weekly results or 50 anime-category results, a 24-hour daily refresh cache, and a dated, clearly marked saved-feed fallback no older than seven days. Check for due refreshes hourly while Home is visible and on foreground return; serve cached data until due. Weekly rankings update through the free API without another APK release. Never upload local watch history to the ranking source or mirror AniList's full database.

Cartoon collections use the small bundled `cartoon-discovery.json` snapshot, not AniList anime categories or invented viewing counts. Curate exact WCO `series` URLs in the Cartoons catalog, preserve original-series identity, and retain Teen Titans, Avatar, and original Scooby-Doo in essentials plus Family Guy and South Park in Adult animation. Ratings are real 0–10 TVmaze averages or null, sorted descending with unknowns last; preserve source-page URLs, the snapshot date, and CC BY-SA 4.0 attribution in ARTWORK-NOTICE.txt. Label them as curated picks with a dated TVmaze ratings snapshot. `tools/refresh_discovery.py --check` validates offline; `--refresh` explicitly fetches only curated show IDs with three workers and shared rate limiting. Do not refresh the whole source catalog on a TV. Keep View all, full WCO browsing, and Movies access separate from ranked discovery.

Keep source/media links internal. Use the source's real skip control or valid timing data for intro skipping; never invent a fixed intro duration. Preserve captions, fullscreen, deliberate pauses, and normal provider initialization.

Write concise, performant code without comments. Keep licenses in separate notice files. Use SQLite queries, streaming catalog imports, 60-title pages, bounded caches/network work, cancellation, and stale-session rejection. Do not render the entire catalog or fetch every episode/video during indexing.

Series covers and episode thumbnails are different. Keep a static cover for each matched series/movie. The URL-only artwork snapshot has 6,874 series and 1,329 movie matches with source URLs and credits; never guess ambiguous remakes. Use `tools/enrich_artwork.py` for developer-side metadata refresh, preserve all four image/provenance fields during catalog refresh, and retain `ARTWORK-NOTICE.txt`. No individual episode artwork belongs in the catalog asset.

For confidently matched anime, ranking queries supply `coverImage.large` posters and `bannerImage` promotional backdrops from the exact `s4.anilist.co` host. Preserve known catalog covers, using the larger AniList poster for missing artwork or a directly matched old AniList thumbnail. A matched ancestor's generic series cover must not become a sequel/remake's poster. Preserve provenance for each image variant and private-frame priority. Keep query/cache version 5 so older tiny-cover feeds refresh. A missing backdrop uses a contained portrait layout, never a stretched poster. Artwork requests and response/cache identities distinguish `poster` and `backdrop` variants. MAL covers request the bounded 300×450 rendition. Series/movie shelves use portrait posters; watched-episode frames remain landscape.

Watched episodes may keep one device-private frame from pause or normal exit. Use the series cover when capture is unavailable or playback ends abruptly. Native Android frames preserve aspect ratio within 160×90/JPEG55, bounded to 64 files/1 MiB; posters are at most 320×480/JPEG75 and backdrops 960×540/JPEG75, sharing a 256-file/16 MiB cache with a 1 MiB download limit per image. Version artwork cache keys to regenerate old tiny thumbnails without erasing history. HTML5 LG/Samsung frames are 192×108 with a private 1 MiB limit; Roku/Samsung AVPlay use the series-cover fallback. Clear history must delete private episode frames and history, preserve favorites/static covers, and prevent a resumed-then-abruptly-killed session from reusing a stale thumbnail. Never upload screenshots, commit them, or put them in the public catalog. Use public capture APIs on the app's own visible video layer; SurfaceView/TextureView capture can be needed when Window copying returns a blank frame.

Android playback starts with the manual cursor off. Preserve the prominent, orange-focused center Pause/Resume control and single-Select playback behavior; Menu enables the toolbar and optional manual cursor. Explicit media play/pause must remain idempotent.

Keep the global catalog topbar/header, count strip, provider/source switch, and search header removed. Search remains in the sidebar; Anime, Cartoons, and Movies use content chips. Preserve section labels and honest feed attribution without recreating the removed header. Keep focus rings and content within the actual viewport while scrolling and resizing. Maintain responsive safe insets and verify 640×360, 960×540, 1280×720, 1920×1080 and 3840×2160. Do not change TV picture calibration or hardcode one model's scale.

Select the highest quality actually offered through supported site-player APIs or visible quality controls. Keep real decoded dimensions separate from the TV's panel resolution. Never fabricate a 4K rendition or bypass provider access controls; a source offering only 800p remains 800p.

## Friendly Windows setup

For someone who wants to install the app without coding, use `Setup-Cartoon-Watch.cmd` from the fully extracted project folder. It opens the `setup-tv.ps1` setup window for compatible Android-based Fire TV, Android TV, and Google TV devices. This prebuilt-app path downloads verified Android connection tools and the published GitHub Release APK, or uses an existing local `outputs/Cartoon-Watch.apk`. It does not require Python, Java, Node, Android Studio, administrator access, Codex, or Claude. Keep the beginner quick start at the top of README.md, with developer build instructions clearly separated below it.

Confirm the actual TV platform before using the helper. Obtain that TV's real address, connection port, and any required pairing values from the user/device. Do not scan the LAN, assume a port for every Android TV, reuse a previous person's private address, or claim this APK installer supports Roku, LG webOS, Samsung Tizen, Apple TV, or Vega OS. Direct other platforms to their client guides and explain that their LAN companion must stay running during playback.

Explain Developer Options/ADB and the TV's Allow prompt before connecting. The user must approve their own device authorization. Reuse authorization already granted in the current session; do not add repeated permission gates. Use only pairing features actually implemented by the helper, with the pairing port distinguished from the connect port. An address alone does not establish that an unknown TV is the intended device; inspect its model/platform and compatibility when connecting.

The current GUI takes an explicit numeric IPv4 address and connection port. It has a TV-platform chooser, Check / Connect, and Install Cartoon Watch. Google/Android wireless pairing uses the separate Pairing address, masked six-digit Pairing code, and Pair Google TV controls; return to the main connection address after pairing. It reports the detected model/API before enabling install and does not scan for TVs or repeatedly attempt unauthorized connections. Fire TV's usual `:5555` is a platform-specific instruction, not a universal Android port. Verify the actual helper behavior before documenting additional platforms or controls.

Ordinary helper installs update in place and preserve app data. A signature conflict must stop with a clear explanation; do not automatically uninstall or erase data. Keep release signing keys outside Git and outside downloadable installer/source archives. Download hashes verify the published bytes, not a trusted-publisher certificate or freedom from malware. Do not instruct people to disable antivirus, weaken system security settings, or bypass every Windows warning. If Windows reports a threat, stop and investigate the exact file/source rather than applying a blanket bypass.

## First action for a new TV

Identify the actual TV platform first. Ask for its model/OS when unknown while preparing independent host work. Never reuse the original TV's private address, port, model, density, or WebView assumptions.

- **Fire OS:** Tell the user to enable Developer Options and ADB Debugging, then accept the TV's computer-authorization popup. If hidden, Settings → My Fire TV or Device & Software → About → select the device name seven times. Find its address under About → Network.
- **Android TV/Google TV:** Tell the user to enable Developer Options by selecting Android TV OS build/Build seven times under About, then enable USB or Wireless debugging and accept authorization. Wireless debugging may require pairing and a different connect port; use the displayed values rather than assuming 5555.
- **Roku:** Use Roku Developer Mode and the development installer, not ADB. Follow `clients/roku/README.md`, obtain the actual Roku address, and keep its developer password private. Installing a development channel can replace an existing sideloaded channel; establish whether one is present before replacing it.
- **LG webOS:** Use LG's Developer Mode app, developer-account login, Dev Mode Status/reboot, Key Server, and the webOS `ares` tools. Follow `clients/lg/README.md`. Account login, displayed key/passphrase, and renewable developer session require the user's participation. No ADB.
- **Samsung Tizen:** Use TV Developer Mode, its requested development-computer address/reboot, Tizen Studio/SDB, and the user's Samsung certificate/device authorization. Follow `clients/samsung/README.md`. Keep certificate files and passwords private. No ADB.

When Android ADB is unauthorized or missing, explicitly explain the enable/Allow steps and wait for the user. Do not repeatedly retry, scan the LAN, guess among devices, or disable unrelated security settings.

Official Android setup: [Amazon](https://developer.amazon.com/docs/fire-tv/connecting-adb-to-device.html), [Android TV](https://developer.android.com/training/tv/get-started/create), [wireless debugging](https://developer.android.com/tools/adb#connect-to-a-device-over-wi-fi). Platform client READMEs link their official Roku/LG/Samsung instructions.

## Build and install

1. Inspect host tools and the intended platform. Prefer the friendly Windows helper for an unchanged published Android APK. Android source builds require Python 3.10+ and a full JDK 17+; Java 22 is the locally exercised build path. The companion requires Node 22+, Python, and Java. Native Roku/LG/Samsung packaging has its own tool requirements.
2. For Android, use `python install.py --inspect --device ADDRESS:CONNECT_PORT` and verify model, API, ABI, display, density, and WebView. Omit `--device` only when exactly one intended authorized device exists. API 23+ is required. Non-Android TVs cannot use this APK; use their separate client rather than flashing/rooting/replacing the TV OS. Vega OS is not an Android APK target.
3. Build and verify source changes on the PC before deployment. Android: `python build.py`, or the existing Windows `build.ps1`. The Python builder supports official Windows/macOS/x86-64 Linux SDK archives; only Windows has local build verification. For an unchanged published APK, use the Windows helper's download verification and detected-device checks; do not require source-build tools for that path. Use the appropriate client README for Roku, LG, or Samsung.
4. Run checks appropriate to the change: bounded catalog/search, correct episode payloads, actual playback when accessible, pause/seek/captions, source-provided intro skip, cancellation/background handling, and controlled primary-source failure. Distinguish live playback, fixtures, mocks, and physical-device testing.
5. Install Android with the Windows helper, or use `python install.py --device ADDRESS:CONNECT_PORT --no-build` for the manual/source path. Both update in place with `adb install -r`. Do not uninstall signature-incompatible apps, erase data, or change unrelated settings automatically. The user's build/install request authorizes ordinary reversible setup; do not add repeated permission gates.
6. For Roku/LG/Samsung, start the LAN companion, obtain the TV's real developer connection, build the client package, and follow its installation/signing instructions. Use the companion's printed LAN service URL, not `localhost` on the TV. Keep the companion running during playback.
7. Validate on the intended device when available. Remove temporary debugging forwards and leave the app at its catalog. Missing pairing, authorization, credentials, or device selection requires the minimum necessary user input while independent preparation continues.

For the shared catalog UI, install the companion's dependencies/browser, then run `node tests/ui.cjs` from the root. It checks real-index-backed UI fixtures at 960×540 and 1920×1080; it does not verify provider streaming. `PLAYWRIGHT_EXECUTABLE_PATH` can select an existing browser. Run `node tests/header-layout.cjs`, `node tests/artwork-ui.cjs` and `node tests/quality.cjs` for responsive layout, thumbnail state and offered-quality fixtures. Use the platform client READMEs for their additional checks.

## Project map and voice

`app/` contains Android Java and the bundled UI. `build.py`/`build.ps1` fetch verified build dependencies; `install.py` inspects/installs Android. `tools/refresh_catalog.py` refreshes the public WCO metadata snapshot; `tools/enrich_artwork.py` maintains small, attributable cover URLs without image assets. `companion/` provides LAN catalog and compatible-stream resolution for `clients/roku/`, `clients/lg/`, and `clients/samsung/`; `clients/webtv/` shares LG/Samsung UI and packaging.

Start the companion with `npm install`, `npm run setup`, and `npm start` from `companion/`. Its default port is 8765; use the actual LAN address it prints. Roku, LG, and Samsung cannot embed the Android website player, so verify the resolved stream's native codec/player compatibility.

Preserve native media/voice transport and voice-keyboard input. Samsung public VoiceInteraction callbacks are optional, runtime-detected APIs. Global assistant catalog search is not automatically registered. Custom Alexa/Amazon skill, account, cloud-bridge, and tunnel integration was cancelled; do not add or claim it. Standard platform playback transport needs no separate Amazon Developer account and depends on platform routing. Keep signing material outside Git. The companion stays on the private LAN and needs no hosted service or subscription.
